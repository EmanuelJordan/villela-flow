# Decisões técnicas

| Decisão | Motivo |
|---|---|
| **Next.js 16 (App Router, Turbopack)** | O plano previa Next 15; o npm instalou a estável atual (16.2). Padrões idênticos (Server Components/Actions); adaptações: `middleware.ts` → `proxy.ts`, `next lint` removido → `eslint .`. |
| **Supabase cloud Pro, sa-east-1** | Pro inclui 100k MAU — 200 usuários usam 0,2%. Latência baixa no Brasil. |
| **Chaves novas `sb_publishable`/`sb_secret`** | As chaves legadas `anon`/`service_role` serão descontinuadas até o fim de 2026. A secret NUNCA leva prefixo `NEXT_PUBLIC_`. |
| **OAuth Google separado do login** | O Supabase Auth não renova `provider_token` e o perde após refresh de sessão (issues abertas há anos). Fluxo próprio server-side com refresh token criptografado (AES-256-GCM) é a prática recomendada. |
| **Tema claro com acentos ciano** | Escolha do usuário. Paleta extraída e verificada de grupovillela.com.br: ciano #00BCE5/#55C2E6/#18C1E8, petróleo #0A323C, off-white #F6F7F3, teal #3CB5C9/#116780. Fontes Outfit + Space Grotesk (as do site). Botões primários com texto petróleo sobre ciano, como os CTAs do site da marca. |
| **Parser do diagnóstico** | `villela-v1` implementado sobre as rotas de diagnóstico do site da Villela; o stub segue atendendo qualquer outra URL, então a demo não depende da API externa. |
| **Agenda por link, não por busca de lead** | Pedido do usuário: o campo "Cliente (lead)" virou "Link do diagnóstico", que preenche título e descrição. O vínculo com lead continua existindo pelo deep-link `/agendamento?lead=<id>` vindo do funil. |
| **Dois funis que coexistem (2026-07-22)** | `/prospeccao` (o antigo `/funil`) cobre o pré-reunião com `leads` + `funil_estagios`; `/funil` é o novo Funil Unificado, do agendamento ao contrato pago. Espelha o sistema atual. (Superado depois: a aba `/prospeccao` foi removida e o Funil Unificado absorveu a etapa de prospecção.) |
| **Etapa do funil é derivada, não armazenada** | Não existe coluna de estágio: `classificar.ts` resolve em cascata (pagamento > contrato > proposta > status da reunião), igual ao sistema de referência. Assim não há card em "Contrato pago" sem pagamento. O preço é que arrastar grava a *causa*, não a posição — daí a matriz de `transicoes.ts` e o bloqueio de retrocesso entre blocos. |
| **Cascata em TS, não view SQL** | A referência calcula `bloco`/`etapa` numa view `funil_unificado`. Aqui é função pura testável, no padrão de `escopo.ts`/`ranking.ts`; evita `security_invoker` e mantém o teste junto do resto. Se o volume crescer, promover para view. |
| **"Expirando" é selo, não coluna** | Na referência uma proposta a ≤2 dias do vencimento **sai** da coluna dela e reaparece em "Expirando" — o vendedor perde o card de vista na hora mais crítica. Aqui vira badge no card, e ele fica onde está. Sete colunas em vez de oito. |
| **Card com três linhas e métrica por coluna** | Em Agendados o que pesa é *quando*; em Proposta, *quanto foi abatido*; em Contrato pago, *o que entrou*. A referência mostra todos os campos em todas as colunas — é o grosso da poluição visual. O resto vai para o painel lateral. |
| **Auth simples na demo** | Decisão do usuário para acelerar a demo. Schema JÁ preparado para silos por equipe (team_id em tudo + `private.user_team_id()`) e aprovação de gerente (`profiles.status`). Ativação preparada no schema (silos por equipe + aprovação de gerente). |
| **Kanban: drop ao fim da coluna** | Reordenação intra-coluna ficou fora do MVP (YAGNI); ordem por `posicao`. Refinar após os prints do sistema atual. |
| **zod v4** | `z.string().uuid()/.email()/.url()` estão deprecated (funcionam); migrar para `z.uuid()` etc. se um lint de deprecation entrar. |
| **Login split-screen com vídeo** | Pedido do usuário (2026-07-12): metade esquerda logo + formulário, metade direita vídeo em loop com pegada de negócios. Vídeo ativo: stock Mixkit #41541 (aéreo de cidade, 720p, 7,7 MB, licença livre) em `public/videos/login-bg.mp4` — escolha do usuário em 2026-07-13 após testar o institucional. O institucional do cliente segue em `videos/` (staging gitignored, HEVC); se voltar, transcodificar para H.264 8-bit (HEVC não toca em todo navegador). Trocar o arquivo troca o vídeo. Fallback estático de marca quando o vídeo falha. O matcher do `proxy.ts` precisou excluir `.mp4/.webm` — sem isso o middleware redirecionava o vídeo (estático) para /login. |
| **Logo recriada em SVG** | Sem arquivo oficial da logo; lockup recriado em `src/components/brand/villela-logo.tsx` a partir do print do usuário (tile ciano + linha de performance + wordmark). Quando o cliente mandar o asset oficial, trocar só nesse componente. |
| **Home por papel (2026-07-13)** | Afiliado (`sdr`) vê só o próprio trabalho, gestor (`gerente`) vê a equipe + ranking, VP (`vp`, migração 0003) vê tudo + comparativo de equipes. Escopo aplicado na camada de aplicação (`src/lib/escopo.ts` → `.match()` nas queries); RLS de demo intocado. Só a Home filtra por papel nesta etapa — Funil/Agendamento continuam visão compartilhada. |
| **VP pertence à Matriz no banco** | `team_id` é NOT NULL nas tabelas de negócio e `requireContexto` exige equipe; o papel `vp` é o que dá visão global na Home. |
| **Funil de estágios compartilhado** | As 3 equipes do seed usam o mesmo conjunto de `funil_estagios` (team da Matriz) — o Funil e as métricas consultam sem filtro de team. Dívida consciente se equipes precisarem de funis próprios. |
| **Fechamento atribuído ao owner do lead** | No ranking/comparativo, o crédito do fechamento vai para `lead.owner_id` (quem carrega a carteira), não para o `actor_id` do evento. Pode divergir sutilmente dos cards de métricas (que contam eventos) se um lead trocar de dono — aceitável na demo. |
| **Ação rápida "Nova proposta" desabilitada** | Módulo de propostas ainda não existe; o cartão fica com selo "Em breve" (aria-disabled, sem link) pronto para ser ligado quando a página chegar. |
